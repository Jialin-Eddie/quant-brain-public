## Problem
Data files (`.csv`, `.parquet`) get accidentally committed to git, bloating repository history and potentially leaking proprietary data. Once committed, removing them from git history requires destructive rewrites.

## Root Cause
- `git add .` or `git add -A` picks up generated output files
- Developers add `!outputs/*.csv` exceptions to `.gitignore` thinking it's convenient
- CI/CD scripts that auto-stage all changed files

## Solution
```bash
# WRONG — stages everything including generated CSVs
git add .
git add -A

# CORRECT — stage only source files explicitly
git add src/my_script.py
git add .gitignore

# Verify nothing sensitive is staged before committing
git diff --staged --name-only
```

**.gitignore must contain (never remove these):**
```
*.csv
*.parquet
*.feather
data/
outputs/
```

## Prevention
- **Rule**: Only stage `.py` source files, `.gitignore`, and config files
- **Rule**: Never add `!outputs/*.csv` exceptions to `.gitignore`
- **Check**: Run `git diff --staged --name-only` before every commit to verify staged files
- Data files are always regenerated by running the relevant script — they are not source of truth
